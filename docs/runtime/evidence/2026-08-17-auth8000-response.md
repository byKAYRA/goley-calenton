## 1. Client Request Breakdown (28-Byte Raw Frame on Port 8000)

### Wire Frame:
```
32 18 00 00 ad 9a 9e 93 25 a3 b1 9e 9b 8d a6 00 24 4c 9b c9 62 75 6d 50 51 20 4c 60
```

- `0x32`: AniPark Magic Header
- `0x0018` (`24`): Payload wire length
- `0x00`: Sequence Counter (`seq = 0`)
- `24` bytes ciphertext: Dummy bytes removed via `sub_A6A4B0(24)` (8 dummy bytes removed -> 16 bytes ciphertext)
- Decrypted via XOR stream cipher (`sub_A6A5E0` / `sub_A6A8C0`):
  ```
  00 00 00 00 03 00 00 00 [4-byte client nonce] 1f 00 00 00
  ```
  - `offset 0..3`: `0x00000000` (Opcode 0, sub 0: Auth Challenge Request)
  - `offset 4..7`: `0x00000003` (Client Protocol Subversion / Auth Version = 3)
  - `offset 8..11`: 32-bit Client Nonce / Session Seed
  - `offset 12..15`: `0x0000001F` (Client Build / Environment Identifier = 31)

## 2. Client Dispatcher Architecture & Response Schemas

### Port 8000 Auth Dispatcher (`sub_A74C60`)
Called by `sub_A98770` when `v1[8205] == 0`:
```c
char __thiscall sub_A74C60(unsigned __int8 *this, int __return_address, char a3)
{
  switch ( a3 )
  {
    case 0:  return sub_A74770(__return_address); // Packet 1 Response (Cipher Setup)
    case 8:  // Error Popup & Connection Drop
    case 11: return sub_A749E0(this);             // Packet 2 Response (Login OK + Redirect)
  }
}
```

#### Packet 1 Response Schema (`sub_A74770`):
- `offset 0..3`: `0x00000000` (Opcode 0 sub 0)
- `offset 11`: `0` (Substitution Table Index 0)
- `offset 12..22`: `"RealMadrid\0"` (10-byte XOR stream key)
- `wire_len`: 36 bytes (`seq = 0`)
- **Effect**: Configures XOR cipher, updates auth stage to 2, and sends Packet 2 (371-byte credentials with username `"TestUser"`).

#### Packet 2 Response Schema (`sub_A749E0`):
- `offset 0..3`: `0x7F000000` (Opcode 11 sub 0)
- `offset 4..7`: `0x00000001` (SessionID Token 1)
- `offset 8..11`: `0x00000001` (AccountID Token 2)
- `offset 15..18`: `0x00000001` (Handoff Nonce Token 3)
- `offset 22..23`: `2270` (`0x08DE`, Entry Port)
- `offset 26..29`: `213.74.179.12` (`0x0CB34AD5`, Entry IP)
- `wire_len`: 44 bytes (`seq = 1`)
- **Effect**: Closes Port 8000 connection (`sub_A690B0`), calls `sub_A69B10` to connect to `213.74.179.12:2270`, and upon connection sends the 285-byte handoff frame (`sub_A7EB10`).

## 3. Disassembly Analysis of "Hata Kodu 93" (`sub_A98770`)

In `sub_A98770`:
```c
if ( v1[8465] == 0 )
{
  if ( sub_402EE0(...) == 0
    || v1[8204] == 0
    || sub_A68F40() != 0
    || (v5 = *((_DWORD *)v1 + 1), HIBYTE(v18) = 1, *(_BYTE *)(v5 + 113) != 0) )
  {
    HIBYTE(v18) = 0; // Safe: no error
  }
  if ( HIBYTE(v18) != 0 )
  {
    sub_B209B0(21, 93); // <--- TRIGGERS HATA KODU 93 POPUP!
    ...
  }
}
```

### Exact Conditions for Hata 93:
1. `v1[8204] != 0` (Login session state is active).
2. `sub_A68F40() == 0` (Connection 1 to Port 2270 is disconnected / state == 0).
3. `*(_BYTE *)(v5 + 113) == 0` (ProudNet is not yet connected).

### Root Cause of Previous Hata 93:
- Sending a premature unrequested Hero Slots frame (`sub_A71510`) before ProudNet connected caused `sub_A6EF80` to evaluate `*(_BYTE *)(v5 + 113) == 0` and return `-1`.
- This triggered `sub_A690B0()` on the client, which closed the Port 2270 socket.
- On the subsequent tick of `sub_A98770`, `sub_A68F40()` returned `0`, causing `sub_B209B0(21, 93)` to fire.

### Exact Resolution:
On Port 2270, the server responds with 3 frames in strict sequence:
1. **Frame 1**: Cipher Setup (Opcode 0 sub 0, `"RealMadrid\0"`, `wire_len = 36`, `seq = 0`)
2. **Frame 2**: Session Confirmation (Opcode 0 sub 11 `0x38790000`, 32 bytes plain, `wire_len = 40`, `seq = 1` -> calls `sub_A90D00` / `sub_A8E3F0`, succeeds with `error_code = 0`, unlocks game UI and keeps socket open).
3. **Frame 3**: Channel List (Opcode 13 sub 0 `0x8F000000`, 192 bytes plain: 22 Channel IDs + 22 Channel Statuses, `wire_len = 212`, `seq = 2` -> calls `sub_A6F0A0` / `sub_A6C1C0`).
